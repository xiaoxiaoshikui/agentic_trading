# Implementation Plan (Minimal Top-Conference Track)

## Overview
This plan compresses the ToM project into a publishable minimum: one clear algorithmic contribution plus three critical experiments with reproducible code.

**Goal**: a submission-ready paper with robust, comparable results.  
**Scope**: ToM core + 3 experiments + reproducibility.

---

## A. Core Contribution (single focus)
**ToM-Strategic Decision Rule**
- Input: opponent prediction distribution + technical signal.
- Output: final action and confidence.
- Provide a formal decision rule or objective that explicitly conditions on opponent predictions.
- Keep the system minimal and explainable.

**Deliverable**
- `src/tom/reasoning/strategic.py` with a formal rule + docstring explaining the decision objective.

---

## B. Minimal System Components

### B1. Standardized Interfaces
- `src/tom/base.py`  
  - `MarketState`, `Decision`, `BaseAgent`

### B2. Opponent Models (minimal set)
Implement only what is needed for the 3 experiments:
- `RetailTraderModel` (rule-based)
- `MomentumAlgoModel` (rule-based)
- Optional: `SmartMoneyModel` (LLM) if needed for ToM-Full

### B3. Aggregator
- `src/tom/reasoning/aggregator.py`  
  - Weighted net direction + confidence

### B4. ToM Agent
- `src/tom/agent.py`  
  - Combine technical signal + opponent predictions + strategic rule

### B5. Evaluation Harness
Reproducible, seed-controlled evaluation:
- `src/tom/evaluation/harness.py`
- `src/tom/evaluation/statistics.py`

---

## C. Minimal Experiment Set (Top-conference core)

### E1: Main Performance
**Question**: Does ToM improve performance?
- Compare: `Baseline-Tech` vs `Baseline-LLM` vs `ToM-Full`
- Metrics: Sharpe, Max Drawdown, Win Rate, Profit Factor
- Seeds: 3+
- Assets: BTC, ETH, SOL

### E2: Opponent Model Ablation
**Question**: Which opponent model matters most?
- Compare: `ToM-Full`, `ToM-NoRetail`, `ToM-RulesOnly`

### E3: Recursive Depth
**Question**: What ToM depth is optimal?
- Compare: `Level-1`, `Level-2`, `Level-3`

---

## D. Reproducibility Requirements (non-negotiable)
- Fixed seeds and logged configs
- Fixed data splits (true walk-forward, no repeated periods)
- Summary tables generated by script
- Results saved to `experiments/results/`
